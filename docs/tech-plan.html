# Muse 技术方案

一款极简即时渲染 Markdown 编辑器（对标 Typora），纯 macOS 原生实现。v0.2 将编辑数据所有权、源码区间、异步渲染和验证门槛落实为可执行架构。

macOS 14+Swift 6AppKit · TextKit 2SwiftUIswift-markdown

01结论

技术路线保持不变：使用 AppKit 的 NSTextView（TextKit 2）作为编辑核心，SwiftUI 作为应用外壳，swift-markdown 负责 Markdown 语义解析。

实现边界
  1. NSTextStorage 是编辑期唯一可变文本；NSDocument 不维护第二份可变正文。
  2. 保存内容永远是完整 Markdown 源码；AST、token、渲染属性、图片与主题都是派生状态。
  3. swift-markdown 负责语义 AST，MarkdownTokenScanner 负责精确源码 token。
  4. SourceIndex 显式转换 UTF-8 源码位置与 UTF-16 NSRange。
  5. marker 零宽布局必须先通过 M0 的选区、换行、IME 与辅助功能验证。
  6. undo/redo 只记录源码修改；文本撤销后重新生成渲染。
  7. MVP 可整篇解析，但解析运行在不可变快照上，并用 revision 淘汰过期结果。

工作量：可演示 MVP 约 6～8 周全职；达到可长期日用的稳定程度约 8～12 周。M0 是开工 gate，而不是里程碑末尾的补测。

数据所有权

  • EditorBuffer.textStorage：所有键入、粘贴和行为命令的唯一正文。
  • MuseDocument：拥有 EditorBuffer，从 textStorage.string 生成保存快照。
  • RenderSnapshot：纯值派生数据，不负责保存，也不进入 undo。
  • SwiftUI：只保存文件名、主题、侧栏可见性等 UI 状态。

编辑流

textDidChange → revision + 1 → String 快照
→ 后台解析 AST、token、SourceIndex
→ RenderSnapshot → MainActor 检查 revision
→ 批量应用最新结果

旧 revision 直接丢弃，编辑线程不等待解析。光标变化只查询现有 RenderSnapshot 并更新相交 marker，不重新解析；marked text 区间不做会干扰输入的布局更新。

04核心难点与对策

4.1 源码区间：UTF-8、UTF-16 与 token

swift-markdown 的 SourceLocation 使用 1-based 行号和 UTF-8 字节列；AppKit 使用 UTF-16。SourceIndex 为每行缓存两套起点并执行边界检查。AST 只回答“内容是什么”，TokenScanner 负责 emphasis、代码、标题、列表、链接、转义和未闭合语法的精确 marker。RenderEngine 最终只接收 UTF-16 NSRange。

4.2 marker 隐藏与光标回显

marker 字符始终保留，只改变视觉属性。方案按三级降级：先验证零宽或近零宽；不可靠则改为弱化色与较小字号；只有明确需要完全无缝排版时，才在 Phase 2 评估自定义 NSTextLayoutFragment。M0 必测中文、emoji、组合字符、嵌套强调、跨行选区、换行、鼠标、方向键和 VoiceOver。

4.3 块级编辑行为

列表续行/退出、标题断开、保守自动配对和块识别全部通过标准文本替换接口进入文档 undo manager。自动配对必须尊重选区、转义、已有闭合符号与 marked text；优先使用 NSTextView 的命令和替换入口，不直接吞掉所有 keyDown。

4.4 中文输入法

hasMarkedText 为真时，不对 marked range 应用可能影响输入与布局的属性；上屏后再建立 revision。后台解析不能抢占主线程。人工矩阵覆盖拼音、双拼、五笔和系统英文输入，以及强调、链接、列表、代码围栏内的 Enter/Escape/方向键。

4.5 撤销 / 重做

undo 只包含源码变化；普通键入使用 NSTextView 原生 undo，自动配对和列表续行组成单个 undo group。主题、着色、marker 显隐与图片加载不注册 undo。撤销后重新生成 RenderSnapshot，不使用整篇字符串快照作为正式撤销模型。

4.6 并发与性能

主线程只负责输入、selection 与最新属性应用；后台任务解析不可变快照。旧任务可以取消，但正确性依赖 revision 校验。属性更新优先限制在变化块和可见区域，不把“下一 runloop”当作性能保证。

文档规模输入主线程预算目标
20KB< 8ms P95无可感知延迟
200KB< 16ms P95连续输入不丢帧、不跳光标
1MB不阻塞输入允许渲染滞后，源码编辑仍可用

200KB 不达标时，自建 block index，只重扫受影响块，并低频使用全量 AST 校准；不依赖 swift-markdown 的公开增量解析能力。

4.7 图片

常规 NSTextAttachment 与“源码字符不变”存在冲突。MVP 只提供图片语法样式、路径解析和悬浮/侧边预览；真正行内图片进入 Phase 2，再选择自定义 layout fragment、额外预览行/overlay，或明确引入显示文本与源码映射。
