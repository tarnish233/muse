# Muse 技术方案

一款极简即时渲染 Markdown 编辑器（对标 Typora），纯 macOS 原生实现。v0.6 已收口 M3 光标交互：保留 NSTextView 原生方向键、鼠标与选区语义，并在同一正文上加入安全的源码模式。

macOS 14+Swift 6AppKit · TextKit 2SwiftUIswift-markdown

M3光标交互收口（2026-08-28）

方向键、鼠标命中和选区继续由系统 NSTextView 负责；Muse 只读取系统选区并更新 marker 派生属性。跨行选择会回显所有相交块的源码 marker。

新增“显示 → 源码模式”与 ⌘/。模式切换复用唯一 NSTextStorage，不改字符、不标脏、不进入 undo；输入法 marked text 期间延后属性应用。

Debug、Release 均为 120 tests / 8 suites 全绿；真实窗口已验证方向键穿越 marker、鼠标命中、跨行选区、源码编辑与撤销。M0-3 的完整中文 IME 与 VoiceOver 人工 gate 仍需继续关闭。

00本轮视觉复查（2026-08-27）

本轮对照截图复查发现并修复了四项列表视觉缺陷：

  1. 软换行列表项的一个 paragraph fragment 覆盖多条 NSTextLineFragment。旧实现按整个 paragraph fragment 的高度居中 marker，导致 marker 落在段落中部；现改为锚定首个 textLineFragments.first。
  2. 二级无序 marker 虽然由 AST depth 选择 ◦，字体 fallback 仍可能把 U+25E6 画成实心点。现在由 .museListDepth 驱动 glyph 判定，并在 fragment 绘制层用矢量实心圆、空心圆和方块，确保二级中心留空；绘制层不从源码缩进重新推导 depth。
  3. 首行行框包含 glyph 上下方的 leading；把较小字号 marker 居中到 typographicBounds 会使圆点和序号整体高于正文。现在读取首个 line fragment 的 glyphOrigin.y：有序序号与 checkbox 按 marker font ascender 对齐正文 baseline，无序矢量符号对齐正文 font 的 x-height 视觉中心，不使用固定像素补偿。
  4. 有序 marker 旧按自身宽度从正文列向左回推，等同于右对齐；1. 与 2. 的可见左边界会受字形 side bearing 影响，也无法与无序 marker 共用稳定左边界。现在用段落缩进推导固定 marker 槽，按 Core Text glyph path bounds 补偿可见墨迹左边界；多位序号在槽内适配且不移动正文列。

任务 checkbox 的 checked marker 使用系统 accent 色，unchecked marker 使用 secondaryLabelColor，两者都按浅色/深色外观解析。本轮只完成颜色与绘制，不实现点击切换；checkbox 点击将留到 M4，并通过标准文本编辑把 [ ]/[x] 替换为一次可撤销的源码操作。

本轮新增 6 项真实 TextKit 2/位图回归测试；最新 Debug 全量证据为 109 tests / 7 suites，其中 RendererTests 为 33 项。这组证据验证了首行锚定、无序 marker 的 x-height 对齐、有序 marker 的 baseline 与固定槽位、1./2. 的可见墨迹左边界、98./99./100. 不侵入正文、一级实心与二级空心的实际 fragment 像素，以及任务 checkbox 的外观颜色。

根任务以独立 bundle 启动 Debug App 做了视觉人工复查，已确认长列表 marker 位于第一视觉行、无序 marker 与正文 x-height 居中、有序序号与正文基线一致、二级 marker 明确为空心、checked checkbox 使用蓝色强调而 unchecked checkbox 使用灰色轮廓。本结果只覆盖本轮列表/checkbox 外观，不等同于 M0-3 的 IME、VoiceOver、零宽 marker、完整外观热切换等清单已全部完成。

01结论

技术路线保持不变：使用 AppKit 的 NSTextView（TextKit 2）作为编辑核心，SwiftUI 作为应用外壳，swift-markdown 负责 Markdown 语义解析。

实现边界
  1. NSTextStorage 是编辑期唯一可变文本；NSDocument 不维护第二份可变正文。
  2. 保存内容永远是完整 Markdown 源码；AST、token、渲染属性、图片与主题都是派生状态。
  3. swift-markdown 负责语义 AST，MarkdownTokenScanner 只补编辑中的未闭合语法。
  4. SourceIndex 显式转换 UTF-8 源码位置与 UTF-16 NSRange。
  5. marker 零宽布局必须先通过 M0 的选区、换行、IME 与辅助功能验证。
  6. undo/redo 只记录源码修改；文本撤销后重新生成渲染。
  7. MVP 可整篇解析，但解析运行在不可变快照上，并用 revision 淘汰过期结果。

工作量：可演示 MVP 约 6～8 周全职；达到可长期日用的稳定程度约 8～12 周。M0 是开工 gate，而不是里程碑末尾的补测。

└──────────────────────────────────────────────────────┘

数据所有权

  • EditorBuffer.textStorage：所有键入、粘贴和行为命令的唯一正文。
  • MuseDocument：拥有 EditorBuffer，从 textStorage.string 生成保存快照。
  • RenderSnapshot：纯值派生数据，不负责保存，也不进入 undo。
  • SwiftUI：只保存文件名、主题、侧栏可见性等 UI 状态。

编辑流

textDidChange → revision + 1 → String 快照
→ 后台解析 AST、token、SourceIndex
→ RenderSnapshot → MainActor 检查 revision
→ 批量应用最新结果

旧 revision 直接丢弃，编辑线程不等待解析。光标变化只查询现有 RenderSnapshot 并更新相交 marker，不重新解析；marked text 区间不做会干扰输入的布局更新。

04核心难点与对策

4.1 源码区间：UTF-8、UTF-16 与 token

swift-markdown 的 SourceLocation 使用 1-based 行号和 UTF-8 字节列；AppKit 使用 UTF-16。SourceIndex 为每行缓存两套起点并执行边界检查。AST 负责语义与精确源码区间，MarkdownTokenScanner 只补编辑中的未闭合语法；RenderEngine 最终只接收 UTF-16 NSRange。

4.2 marker 隐藏与光标回显

marker 字符始终保留，只改变视觉属性。列表/任务 marker 使用近零宽属性，块级视觉则通过自定义 NSTextLayoutFragment 绘制。M0 必测中文、emoji、组合字符、嵌套强调、跨行选区、换行、鼠标、方向键和 VoiceOver。

4.3 块级编辑行为

列表续行/退出、标题断开、保守自动配对和块识别全部通过标准文本替换接口进入文档 undo manager。任务 checkbox 点击切换属于 M4：命中图形后将源码 [ ]/[x] 标准替换为一次 undo 操作；当前只绘制 checkbox，尚未提供点击切换。自动配对必须尊重选区、转义、已有闭合符号与 marked text；优先使用 NSTextView 的命令和替换入口，不直接吞掉所有 keyDown。

4.4 中文输入法

hasMarkedText 为真时，不对 marked range 应用可能影响输入与布局的属性；上屏后再建立 revision。后台解析不能抢占主线程。人工矩阵覆盖拼音、双拼、五笔和系统英文输入，以及强调、链接、列表、代码围栏内的 Enter/Escape/方向键。

4.5 撤销 / 重做

undo 只包含源码变化；普通键入使用 NSTextView 原生 undo，自动配对和列表续行组成单个 undo group。主题、着色、marker 显隐与图片加载不注册 undo。撤销后重新生成 RenderSnapshot，不使用整篇字符串快照作为正式撤销模型。

4.6 并发与性能

主线程只负责输入、selection 与最新属性应用；后台任务解析不可变快照。旧任务可以取消，但正确性依赖 revision 校验。属性更新优先限制在变化块和可见区域，不把“下一 runloop”当作性能保证。

文档规模输入主线程预算目标
20KB< 8ms P95无可感知延迟
200KB< 16ms P95连续输入不丢帧、不跳光标
1MB不阻塞输入允许渲染滞后，源码编辑仍可用

200KB 不达标时，自建 block index，只重扫受影响块，并低频使用全量 AST 校准；不依赖 swift-markdown 的公开增量解析能力。

4.7 图片

常规 NSTextAttachment 与“源码字符不变”存在冲突。MVP 只提供图片语法样式、路径解析和悬浮/侧边预览；真正行内图片进入 Phase 2，再选择自定义 layout fragment、额外预览行/overlay，或明确引入显示文本与源码映射。

4.8 块级视觉：绘制层

列表圆点/序号/复选框、引用竖线、代码块背景和分隔线必须通过自定义 NSTextLayoutFragment 绘制。2026-08-27 截图复查发现：软换行 marker 不能按整个 paragraph fragment 高度居中，必须锚定首个 NSTextLineFragment 的真实 line geometry；二级无序 marker 不能只依赖字体 fallback 的 ◦，否则可能视觉上仍是实心点。当前实现由 AST 写入的 .museListDepth 驱动 glyph 判定，并用矢量实心圆/空心圆/方块绘制；同层有序/无序 marker 使用段落缩进推导的固定槽位，有序文本按 Core Text glyph path bounds 补偿可见左边界，多位序号在槽内适配且不移动正文列。

任务 checkbox 的 checked marker 使用系统 accent 色，unchecked marker 使用外观感知的 secondaryLabelColor，浅色/深色均由调色板解析。本轮只完成颜色与绘制，不实现点击切换；图形命中、源码 [ ]/[x] 标准文本替换和一次撤销列入 M4。

本轮新增 6 项真实 TextKit 2/位图回归测试；最新 Debug 全量证据为 109 tests / 7 suites，其中 RendererTests 为 33 项。

独立 Debug App 窗口的本轮列表/checkbox 外观人工复查已通过；完整 M0-3 的 IME、VoiceOver、零宽 marker 与外观热切换清单仍需逐项执行。
